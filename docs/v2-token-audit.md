# v2 token audit (P1.4)

**Inventory only, per `docs/v2-spec.md`'s P1.4 section: "Convert nothing
here. Conversion is P2, in its own sessions."** Every count below was
produced by direct, reproducible commands against the real files in this
repo (not estimated), and spot-checked line-by-line before being recorded
here. Re-run the commands in each section's own note to regenerate a count
if the file changes before P2 starts.

## Scope and structure

This codebase has **no per-component directory structure** — no
`public/components/`, no `public/css/`. The real layout is:
- `public/styles.css` — one 2,354-line stylesheet.
- `public/moonlit-shrine-themes.css` — the actual 53 per-theme colour
  definitions (generated by `scripts/generate-themes.js`), imported by
  `styles.css`. **Out of scope for this inventory** — that file *is* the
  intentional colour source of truth, not stray literals to clean up.
- `public/js/*.js` — 25 files, flat, one directory.

So "grouped by directory" below means, in practice: `public/styles.css`
grouped by its own `/* ---------- Section ---------- */` comment blocks
(the file's real substructure), and `public/js/` grouped by individual
file.

## `public/styles.css`: hardcoded colour literals outside the token block — 4 occurrences

Command:
`grep -n "rgba(\|rgb(\|#[0-9a-fA-F]\{3,8\}" public/styles.css` (excluding the
`:where(:root)`/`[data-text-size]`/`[data-text-weight]` token-definition

All 4 are `rgba()` overlay/scrim darkening, all in the Series card section:

| Line | Declaration |
| --- | --- |
| 1115 | `background: rgba(0,0,0,0.65);` |
| 1215 | `background: linear-gradient(75deg, transparent 30%, rgba(255, 255, 255, 0.4) 50%, transparent 70%);` |

Zero hex codes and zero raw `hsl()`/`hsla()` literals exist outside the

Colour-literal cleanup in `styles.css` itself is a very small, contained
item compared to font-size and spacing.

## `public/js/`: inline hardcoded literals

Checked every `.style.X =` / `.style.setProperty(...)` call, every inline
`style="..."` template-string attribute, and every canvas `ctx.font`/
`ctx.fillStyle` call across all 25 files.

**Not relevant (data-driven, not a hardcoded design literal) — excluded:**
- `atmosphere.js:66-91` — `--leaf-*`/`--f-*` custom properties set from
  `rand(min,max)` (animation randomization, not fixed values).
- `events.js:185,188-189` — tab-pill slider position from measured DOM
  geometry (`offsetLeft`/`offsetWidth`).
- `events.js:1561-1563` — ripple effect size/position from click
  coordinates and measured element size.
- `render.js` progress-bar/stagger-delay/background-image inline styles —
  all computed from data (`dataset.targetWidth`, `staggerDelayMs(index)`,
  an image URL), not literals.
- `render.js:506`, `screenshotImport.js:90`, `malImport.js:128` —
  `style="color:var(--faint)"` — already tokenized.
- `statsExport.js`'s `fillStyle`/`strokeStyle` calls — already read live CSS
  custom properties via `getComputedStyle` at draw time (`readColors()`,
  lines 19–34), not hardcoded colours.

Whether pixel dimensions for an *exported PNG* count as "spacing" for token
purposes is a P2 scoping question, not answered here.

## A second colour source outside "components," flagged for P2's awareness

`public/js/themes.js:10-64` — a flat data array of the app's ~54 colour
themes, each with `accent1`/`accent2` hex literals (100+ hex codes total),
used only to render theme-picker swatch preview dots (the actual per-theme
CSS custom properties live in `public/moonlit-shrine-themes.css`, already
out of scope above). This is a data/config registry, not a stray literal in
a component — flagged here so P2 explicitly decides whether to account for
it or exclude it the same way the CSS theme file is excluded, rather than
it being silently forgotten.
