# Anime Tracker v3.0: "Next Level" program

You are Claude Code working in the anime-tracker repository (currently v2.3.0 on `main`, tag `v2.3.0`). Your job is to take this app to v3.0: a safer foundation, a far better design, a real motion system, a smoother flow and a set of new features. The work runs in phases. **Run autonomously from Phase 0 to the end of Phase 7 without waiting for me.** Each phase ends in a self-verified checkpoint, not an approval gate. The only hard stops are listed under "Autonomy" below.

## 0. Ground rules (read before anything else)

### Carried over from v2 and non-negotiable
- **Git safety.** Never run: `git reset --hard`, `git clean`, `git branch -d/-D`, `git checkout .`, `git restore` over uncommitted work, `git switch --discard-changes`, `git commit --amend`, `git rebase`, `git push --force`, `git rm`, `git worktree remove`, `rm -rf`, or anything else that discards work. Run `git status --porcelain` before any branch operation, and stop if the tree is not clean.
- **Never delete files.** Retiring files means `git mv` into `docs/archive/` or `archive/` (see Phase 7), which keeps everything reachable. Superseded code inside a file you are refactoring may be removed as part of that refactor.
- **User data (Class A) is sacred.**
  - It is never evicted, never pruned and never touched by a migration that has not passed a dry run on a copy.
  - Any new Class A store or field extends export, snapshot, checksum and restore in the same change (v2 spec rules 3 and 3a).
  - Tests never touch the real data directory.
- **Invariants you must not break**, whatever you refactor:
  - `library.json` is written only as tmp, then fsync, then rename. It is never written while corrupt or too new, and never replaced by an empty library while backups or snapshots exist.
  - Every Class A write goes through one single-writer lock. The If-Match check and the write stay in one critical section.
  - `events.jsonl` is append-only. Restore unions by id. Reset renames the log and never deletes it.
  - `counters = baseline + fold(log)`.
  - Snapshots are verified at build, at read-back and before restore. The pinned snapshot never rotates. Invalid files are quarantined, never deleted.
  - Class B eviction touches only `CLASS_B_STORES` and never evicts corpus entries that are in the library.
  - A schema newer than the app is never written (409 `tooNew`).
- **Copy and config.**
  - All user-facing copy is English and goes through the copy registry.
  - Adjustable thresholds live in `config/tuning.js`. Schema versions, store names, event type strings and stable IDs live in their own domain modules.
- **Runtime dependencies.** The app keeps **zero runtime dependencies**. Pinned devDependencies (esbuild, postject, rcedit and similar) are allowed without asking.
- **The v2 docs are frozen.**
  - Do not edit `docs/v2-spec.md`.
  - The v2 substep process (P-ids, the runnability matrix, file ownership) is over. v3 uses the lighter process below.

### v3 process
- **Branches.**
  - One branch per phase, `v3/<phase-id>-<short-name>`, created from `main` and merged back into `main` (`git merge --no-ff`) as soon as its checkpoint passes. Push `main` and the phase branch to `origin` after each merge. Never force-push.
  - Never create tags or GitHub releases. That is the one step I do myself (see the release checkpoint).
- **Commits.** Use `v3(<phase-id>): <what changed>`. Keep them small and reviewable, and don't mix unrelated changes in one commit.
- **Plan and progress files.**
  - `docs/v3-plan.md` is created in Phase 0 and holds the plan, decisions and acceptance criteria.
  - `docs/v3-progress.md` is a short table plus evidence per phase. Keep it lean: no multi-thousand-line logs.
- **"Done" for every phase** means all of these:
  1. Unit and e2e tests pass.
  2. New behavior has tests.
  3. Perf budgets are measured with `npm run perf`, not guessed.
  4. It is checked in the browser at 1440px and 390px, with reduced motion both on and off.
  5. There is a CHANGELOG entry.
  6. Progress evidence is recorded.
- **Delegation.** Use subagents for parallel review and verification when it helps. Verify their output before relying on it.
- **Checkpoint** (end of every phase, instead of an approval gate):
  1. Run the full unit and e2e suites and the relevant perf/eval scripts.
  2. Check the phase's acceptance list item by item. Use a fresh subagent as an independent reviewer of the phase diff against this brief; fix what it finds.
  3. Write a checkpoint entry in `docs/v3-progress.md`: what changed, evidence (test counts, perf numbers, screenshot paths under `docs/v3-evidence/`), findings from this brief that turned out wrong, and anything deferred.
  4. Merge, push, and continue to the next phase immediately.

### Autonomy
- **Do not ask me questions.** When something is ambiguous, pick the option most consistent with this brief, the Discover spec and the design system, record the choice and the reason under "Decisions made autonomously" in `docs/v3-plan.md`, and continue.
- **Failures.** If an acceptance item or test still fails after three honest fix attempts, record it as deferred with the reason and a failing test marked `todo`, then continue. Only stop the whole run if the failure blocks every later phase (for example the app no longer starts).
- **Context and resuming.** `docs/v3-progress.md` is the resume state. Keep its status table current after every meaningful commit, so that a new session given "resume" can continue from it without re-reading history. Before any context compaction, make sure the table is current.
- **Hard stops (the only reasons to stop and wait for me):**
  1. Anything that would write to my real data directory (`%APPDATA%\anime-tracker\`). Read it and copy it; never write to it. Migrations run on the copy only; the app itself migrates real data when I launch the new build.
  2. Creating tags, publishing GitHub releases, or changing repository settings.
  3. A needed action that is on the git-safety never-run list.
  4. Adding a runtime dependency.
  5. The release checkpoint at the end of Phase 7.

## Phase 1: Safety and correctness (branch `v3/1-foundation-safety`)

Fix these. Each fix gets a regression test.

**Critical**
1. **Reduced motion makes cards invisible.**
   - `.card`, `.discover-card`, `.franchise-card` and `.franchise-seasons` start at `opacity:0`. The global rule at `styles.css:110-111` sets `animation:none!important`, so the `.settled` class from `events.js:1039` never gets added and the cards never appear. This was verified in the browser: the Watched tab shows "12 of 12 series" over an empty area.
   - Fix it so cards are visible by default and entrance animations only add motion (`animation-fill-mode: backwards`). Delete the `.settled` workaround.
   - Add an e2e test with `reducedMotion: 'reduce'` that asserts the cards are visible.
2. **No Host/Origin checks (DNS rebinding and CSRF against `localhost:4321`).**
   - Reject any Host that isn't `localhost`, `127.0.0.1` or `[::1]` on the running port.
   - On non-GET requests, require a matching Origin when one is present and reject `Sec-Fetch-Site: cross-site`.
   - Add a per-launch random token for writes, injected into the served `index.html`.
   - Add the headers `X-Content-Type-Options: nosniff`, a CSP and `frame-ancestors 'none'`. A CSP means removing the inline `onload=` handlers (`render.js:390`, `446`, `1669`) in favor of one delegated capture-phase `load` listener.
   - References: `server.js:1420-1431`, `1610-1618`.

**High**
3. **A second instance writes before it knows the port is taken** (`server.js:105`, `1091`, `2487-2501`). Take an exclusive `DATA_DIR/.lock` (pid plus stale detection) as the very first startup step, before any write.
4. **Events are acknowledged before they reach disk** (`server.js:519-534`). Commit the dedup index only after fsync succeeds. On a write failure, invalidate the index. Validate each event separately and return `rejectedIds`, so one bad event doesn't block the whole outbox.
5. **A failed legacy migration can delete the whole data folder** (`datadir.js:101-105` runs `rmSync` on `DATA_DIR`). Copy into a staging dir and rename it into place, and never remove a directory that existed before.
6. **Schema migrations take no verified snapshot first** (`server.js:245-248`). Before any migration, create a verified snapshot pinned to that schema version and never prune it. v3 adds fields, so this must land before Phase 4.
7. **Overlapping saves cause their own 409** (`app.js:47-61`, `109-115`). Build one save queue: one PUT in flight at a time, and a dirty flag triggers a follow-up save.
8. **Discover drops rebuilds that are requested while one is running** (`discover.js:93-159`). Queue a rebuild to run after the current one.
9. **Status undo restores the whole entry and reverts later edits** (`events.js:579`, `591`, `632-651`). Undo only the fields the action changed. Increment and decrement undo relative to the current value (`events.js:424`, `497`).
10. **Background re-renders destroy in-progress typing** (`app.js:291`, `419-426`). Skip or defer them while a note or episode input has focus.
11. **The slider `settings_changed` bug from the backlog** (`events.js:2896-3053`).
    - Capture each slider's value when the gesture starts and log on `change`.
    - Appearance controls currently pass the same object as both `from` and `to`; fix that.
    - Stop the decoration slider logging on every `input` tick.

**Medium**
12. Clamp `handleIncrement` to `totalEpisodes`.
13. Null-guard `coverImage` in the schedule and search cards (`render.js:1669`, `1776`).
14. Cover downloads: cap the size at about 5MB, require `image/*`, allow only AniList CDN hosts (including after redirects), use a unique tmp name per download, and handle `aborted`.
15. Reject a PUT with no `schemaVersion`. Make migrations 3→4 and 9→10 idempotent and add idempotency tests.
16. Backups:
    - Use tiered retention: the last 50, plus one per day for 30 days, plus one per month.
    - Coalesce backups taken within the same minute.
    - Retry rename with backoff on Windows EPERM/EBUSY.
17. Stats:
    - "Episodes this year" must count episodes actually watched this year, from the event log.
    - Top genres must count completed titles only.
    - Settle the backlog's `duration || 0` vs tuning-fallback question: one rule, applied in both places.
18. Title sort should use the title that is displayed, not always romaji (`state.js:541`).
19. Make body errors return 400, 413 or 415, not 500.

**Checkpoint 1**, with before/after results of a full test run, then continue.

## Phase 2: Render engine and structure (branch `v3/2-render-engine`)

The reason the UI can't animate well or perform: every action rebuilds the entire grid with `innerHTML`. That replays every entrance animation, grows every progress bar again from 0, throws the `+1` pulse away before it can be seen, and drops keyboard focus.

**Target:** stay buildless and dependency-free, and add structure:
- `public/js/core/store.js`: state with a `revision` counter bumped by every mutation, a `Map` from id to entry (replacing the linear `find` in `getEntry`), `subscribe(selector)`, and field-level undo commands.
- `public/js/core/html.js`: an auto-escaping tagged template. Escaping becomes the default instead of a discipline. The CSS `url()` quote issue at `render.js:893`/`2146` goes away with it.
- `public/js/core/reconcile.js`: a keyed list diff on `data-id`. Mutations patch one card. Filter and sort changes reorder the existing nodes.
- `public/js/core/dialog.js`: every overlay moves to native `<dialog>.showModal()`, which gives a focus trap, an inert background and Escape for free. Add `aria-labelledby` and restore focus to the originating card by id.
- `public/js/core/focus.js`: re-focus `[data-id]` after updates.
- Migrate one view at a time into `public/js/views/<view>/{model,view,actions}.js`: the library grid first (the perf hotspot), then detail, discover, schedule, settings, stats. `render.js` and `events.js` shrink with each migration. Do not attempt a big-bang rewrite.
- **Performance work:**
  - Memoize `getGroupedFilteredSorted` on list, revision, filters and sort. It is currently called up to four times per render.
  - Compute sort keys once before sorting, not inside the comparator.
  - Debounce the title filter to about 120ms.
  - Parse the corpus once per etag on the client with 304 support, and keep it parsed on the server.
  - Precompute tag and studio frequencies once per corpus version.
  - Use `content-visibility:auto` on cards, and render in chunks beyond the first ~60.
- Skip global shortcuts while a dialog is open. Only Escape checks this today.
- **Server:** split `server.js` into `src/` modules:
  - `main.js`, which owns the startup order: instance lock → integrity check → snapshot → migrate → counters → pinned snapshot → listen
  - `storage/atomic.js`: one `writeJsonAtomic`, replacing the 8 copies
  - `storage/library.js`, `storage/eventLog.js`, `storage/snapshots.fs.js`, `storage/classB.js`
  - `http/middleware.js`, `http/router.js`
  - `routes/*`
  - `services/*`

  Replace the hand-written inliner in `build-exe.js` with a pinned esbuild devDependency.

**Budgets**, measured with `npm run perf`:
- 2,000-entry library render under 200ms. Currently about 1.0–1.4s.
- Warm Discover load under 400ms. Currently p95 about 4.5s.
- A single `+1` updates exactly one card, verified by a test with a MutationObserver-based assertion.

**Checkpoint 2**, with before/after perf numbers, then continue.

## Phase 3: Design system and motion (branch `v3/3-design-motion`)

Keep the Moonlit Shrine identity (`design/moonlit-shrine-design-system.md` stays the source of truth; update it where v3 changes it), and make the code actually follow it.

### Token cleanup
- The card title is hardcoded to Sora 14.5px (`styles.css:1381`), a legacy font that ignores text size. Put it on the type scale.
- Remove about 30 literal `font-size: Npx` values and 47 raw colors (`rgba`, `white`, `#fff`). The card radius is a literal `11px`. Spacing gaps of 9, 11, 13 and 14px sit off the 4px grid.
- Delete the dead half of `tokens.js` and the `inter.css`/`sora.css` links.
- Add `scripts/check-css-tokens.js`, which fails on hex, `rgb`/`rgba`, `white` or pixel font sizes outside the token files. Wire it into `npm test`.

### Motion system (put it in `:root` and use it everywhere)
```css
:root{
  --motion: 1;
  --dur-press: calc(80ms  * var(--motion));
  --dur-fast:  calc(140ms * var(--motion));
  --dur-base:  calc(220ms * var(--motion));
  --dur-slow:  calc(360ms * var(--motion));
  --dur-emph:  calc(520ms * var(--motion));
  --ease-standard: cubic-bezier(.2,0,0,1);
  --ease-enter:    cubic-bezier(.05,.7,.1,1);
  --ease-exit:     cubic-bezier(.3,0,.8,.15);
  --ease-spring:   cubic-bezier(.2,1.2,.3,1);
  --move-sm:4px; --move-md:12px; --move-lg:24px;
  --stagger: 30ms; /* cap 8 items */
}
@supports (animation-timing-function: linear(0,1)){
  :root{ --ease-spring: linear(0,.13 4%,.44 10%,.77 17%,.96 24%,1.03 31%,1.04 36%,1.02 45%,1 60%,1); }
}
```

These are starting values; tune the spring by eye.

**Rules:**
- Animate only `transform` and `opacity`.
- Exits run at about 70% of the entry duration.
- With the OS reduced-motion setting, or with Motion set to Reduced, movement distances become 0 but 120ms opacity fades stay.
- Motion set to Off disables everything.
- Every keyframe reads the duration tokens. Many hardcode 0.35–1s today, which the animation setting never reaches.

**Remove:**
- `hudScan`
- the endless `shimmerSweep` on progress bars (30+ simultaneous loops on Watching)
- the `epsBlip` loop
- the count-up numbers, which the design system forbids
- ripples on cards and score dots
- two of the three duplicate shimmer keyframes
- the tab underline animating `left` and `width` (replace it with `translateX` plus `scaleX`)

**Build:**
- **View Transitions API.**
  - Tab changes: a 12px directional slide plus crossfade, using `:active-view-transition-type()`.
  - Card cover to detail as a shared element (`view-transition-name: cover-<id>`, set only on the clicked card), with the reverse on close.
- **FLIP fallback** (about 30 lines with `Element.animate`) for status moves and reorders where View Transitions aren't supported. The target tab's count badge pops.
- **+1 micro-interaction.**
  - The button presses to 0.9 and springs back.
  - The progress bar animates `scaleX` from the old value to the new one on `--ease-spring`, never from 0.
  - The episode digit does a single 6px slide-swap.
  - The toast reads "Frieren · episode 19 marked watched · Undo".
- **Completion moment.**
  - The bar turns positive and a hairline sweeps across it.
  - One feather falls from *the card's own position*.
  - The series moves to Watched, with an Undo toast that includes a 1–10 rating row.
  - The whole moment stays under 2.4s.
- **Skeletons** for boot, the detail view and Discover, shown only after 150ms, with one shared, synced shimmer. Replace the "Loading…" text.
- **Exit animations** for dialogs and toasts, using `@starting-style` plus transitions on `overlay`/`display`.
- **Scroll-driven animations**, behind `@supports`:
  - Discover shelves and Stats bars enter with `animation-timeline: view()`.
  - The header condenses on scroll.

## Phase 5: Features (branch `v3/5-features`; split into sub-branches if large)

Every new Class A field follows these steps:
1. An additive migration: nulls for existing entries, nothing rewritten.
2. A dry run against the copy of my real library from Phase 0.
3. Export, snapshot, checksum and restore extended, with a round-trip test.
4. Never run a migration against real data (hard stop 1).

Features:
1. **Event provenance.** Add `meta.source`: `live | import | bulk | backfill` to events. MAL import and bulk "mark watched" currently write fake bulk `episode_watched` events, so a 300-title import reads as a 3,000-episode day. Stats and any future achievements read only `live` events for session and streak logic.
2. **Paused status, rewatches and lossless MAL import.**
   - MAL On-Hold currently maps silently to Watching (`malImport.js:9`), and `my_times_watched`, `my_start_date` and `my_comments` are discarded.
   - Add `paused`, `rewatchCount`, editable `startedAt`/`completedAt`, and wire the currently unreachable `rewatch_started` event.
3. **Watch history (diary).**
   - Per-entry dated watch records: each rewatch is its own record, and each record can carry an optional note.
   - A History view in the detail drawer.
   - A global diary list in Stats.
   - This is a new Class A store. Follow rule 3a.
4. **AniList import by username.**
   - Use `MediaListCollection(userName:, type: ANIME)`, which needs no OAuth.
